# Part 1: Challenge Definition & Problem Analysis

### **1. Executive Summary: The "Administrative Debt" Crisis**

The current Liza platform is a "Ferrari engine with a bicycle’s steering wheel." While the backend (AACE v3.1) supports sophisticated intent-locking and knowledge injection, the frontend places a paralyzing cognitive load on the user. We are currently asking users to be database administrators—manually tagging, creating, linking, and grooming thousands of context items. This manual "Context Management" is unscalable and creates **Administrative Debt** that prevents adoption.

### **2. Critical Friction Points**

#### **A. The "Blank Page" Paralysis (Execution Layer)**

- **The Issue:** Frontline workers enter a Workbook and face an empty chat window and a flat list of 50+ unorganized "Context Items."
- **The Impact:** They don't know what capability to activate. They are forced to "prompt engineer" the system to behave correctly. There is zero visual guidance on what they _should_ be doing.
- **The Gap:** Missing the **"Action Trigger"** layer that connects a user’s intent directly to a Locked Playbook.

#### **B. The "Curator's Dilemma" (Definition Layer)**

- **The Issue:** T-Shaped Experts (Architects) are expected to manually process every "Finding" generated by the system (Triage) and manually input every document via a complex form (Metadata, Scope, Domain, etc.).
- **The Impact:** "Knowledge Rot." The effort required to keep the graph clean is too high, so users stop doing it. The system fills with duplicates and "Draft" items that are never committed.
- **The Gap:** Missing **"Smart Ingestion"** and **"Aggregated Drift Detection"** that automates 90% of the curation work.

#### **C. The "Scope Chaos" (Governance Layer)**

- **The Issue:** Ambiguity in lifecycle actions. Does "Delete" remove it from my screen or the whole company? Where does this finding belong—my project, my team, or the global organization?
- **The Impact:** Fear. Users refuse to share knowledge or delete old items because they are terrified of "polluting" the Global Graph or breaking someone else's workflow.
- **The Gap:** Missing intuitive **"Scope Radials"** and **"Impact Simulation"** that clearly visualize ownership and inheritance.

#### **D. The "Isolated Brain" (Research Layer)**

- **The Issue:** Research is currently a manual task done outside the workflow or via a specific tool in a chat. There is no easy way to pull an external fact and "pin" it permanently to a Process or Task.
- **The Impact:** The graph remains static/stale because new external reality isn't flowing easily into the system.

# Part 2: Master Requirements Document (MRD) v1.0

**Project:** Context & Knowledge Graph UI Refactor **Core Philosophy:** "The Invisible Engine" — The system manages the complexity; the user manages the work.

## **1. Persona-Based Architecture**

The UI must bifurcate into distinct "Operating Systems" for the three core personas.

| Role          | Persona     | Goal                   | UI Environment                        |
| ------------- | ----------- | ---------------------- | ------------------------------------- |
| **Frontline** | _Operator_  | Frictionless Execution | **"The Launchpad"** (Workbook)        |
| **Expert**    | _Architect_ | Structure & Definition | **"The Process Studio"** (Definition) |
| **Leader**    | _Manager_   | Alignment & Oversight  | **"The Command Center"** (Oversight)  |

---

## **2. Functional Requirements: The Launchpad (Frontline)**

### **2.1 The Action Grid (Entry State)**

- **REQ-F-01:** The empty chat history MUST be replaced by a visual **Action Grid**.
- **REQ-F-02:** Cards in the grid MUST map to `PLAYBOOK` items assigned to the workbook’s active Context Bundle via AACE.
- **REQ-F-03:** Each card MUST display: Icon, Title (Action Verb), Subtitle (Methodology/Framework), and "Last Updated" timestamp.
- **REQ-F-04:** A **"Active Missions"** list MUST appear below the grid, showing ongoing task threads with status indicators.

### **2.2 Intent Locking & Guided Execution**

- **REQ-F-05:** Clicking an Action Card MUST trigger the **Locked State** (`locked_playbook_id` in AACE).
- **REQ-F-06:** Visual indicator of Lock: Background tint change + Sticky **Protocol Banner** (showing Playbook Name + Current Step).
- **REQ-F-07:** The Chat Input Placeholder MUST dynamically change to reflect the active `PROCEDURE` step instructions.
- **REQ-F-08:** The "Tools" Sidebar MUST refactor into **"Mission Assets,"** showing _only_ the Read-Only `KNOWLEDGE` items injected by the current lock.

---

## **3. Functional Requirements: The Team Command Center (Expert/Leader)**

### **3.1 Zone A: The Live Pulse (Oversight)**

- **REQ-L-01:** "Workbooks" list MUST handle a **Kanban View**, grouping workbooks by Strategic Outcome/Status (not just list).
- **REQ-L-02:** **Task Lineage Peek:** A hover state on a workbook/task card MUST show the provenance: Source Decision -&gt; Mandate -&gt; Active Task.
- **REQ-L-03:** **Drift Indicators:** The UI MUST flag workbooks where AACE detects high deviation from the Playbook (Visual "Red Dot").

### **3.2 Zone B: The Process Studio (Definition & Curation)**

- **REQ-E-01:** **Smart Ingestion (The Knowledge Loom):**
  - A Drag-and-Drop zone MUST allow bulk upload of unstructured docs.
  - System MUST run an extraction pass and present "Candidate Items" (Playbooks/Directives) for one-click approval.
- **REQ-E-02:** **Drift Aggregation (The Inbox):**
  - Triage tab MUST be replaced by an Inbox clustering similar findings (e.g., "5 Users edited Pricing").
  - Actions MUST include: "Synthesize" (Create new version) or "Dismiss."
- **REQ-E-03:** **Capability Modules:**
  - Global Context items MUST be grouped into visual **"Modules"** (Bundles).
  - Each Module/Item MUST have a **"Scope Radial"**: Dial to set visibility (Local -&gt; Team -&gt; Domain -&gt; Org).
- **REQ-E-04:** **Knowledge Health Dashboard:**
  - Widget showing "Freshness Score" + List of "Stale/Unused" items for Garbage Collection.

---

## **4. Universal Capability: The Research Lens**

### **4.1 Interaction**

- **REQ-U-01:** A persistent **Lens Icon** MUST be visible in the Global Navigation bar on _all_ screens.
- **REQ-U-02:** Clicking triggers a slide-out overlay for ad-hoc queries (Internal/External).

### **4.2 Role-Based "Pinning" Logic**

- **REQ-U-03:** The "Add/Pin" button on search results MUST behave differently by role:
  - **Frontline:** Pins finding to **Current Workbook Context** (Local/Instance).
  - **Manager:** Pins finding to **Task/Brief** (Delegation Context).
  - **Expert:** Pins finding to **Global Playbook/Bundle** (Structural/Permanent).

---

## **5. Logic & Governance Requirements**

### **5.1 Lifecycle & Inheritance**

- **REQ-G-01:** **Delete Disambiguation:** The UI actions MUST separate distinct intents:
  - _Unpin:_ Remove from local session.
  - _Eject:_ Remove from Bundle.
  - _Deprecate:_ Mark legacy/archive.
  - _Destroy:_ Hard delete.
- **REQ-G-02:** **Context Stack:** An "Info" modal MUST visualize the hierarchy of active context (Global -&gt; Domain -&gt; Local) so users see what overrides what.

### **5.2 Safety & Simulation**

- **REQ-G-03:** **Impact Simulator:** Before an Expert saves a Global Change, the system MUST simulate and display: "This change impacts \[X\] Active Workbooks."
- **REQ-G-04:** **Versioning:** Experts MUST choose between "Soft Push" (New projects only) or "Broadcast" (Force update active locks).

---

## **6. Backend Alignment (AACE v3.1)**

- The **Action Grid** triggers `locked_playbook_id`.
- The **Context Stack** corresponds to the hierarchical assembly of `DIRECTIVE`, `KNOWLEDGE`, and `PROCEDURE`.
- The **Scope Radial** maps to the `domain_scope` JSONB field (`["SALES", "OPERATIONS"]`).
- The **Drift Inbox** consumes the feedback loop data from the `NERVOUS SYSTEM`.
